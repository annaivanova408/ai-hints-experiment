# Эксперимент с комментариями

Отдельная платформа для внутрисубъектного исследования комментариев трёх типов: ИИ, эксперт и контроль. Проект не связан с платформой `education` и разворачивается независимо.

## Локальный запуск

```bash
docker compose up --build
```

После запуска откройте [http://localhost:3010](http://localhost:3010).

Данные сохраняются в PostgreSQL 16. Контейнер базы использует отдельный постоянный Docker-том `postgres_data`; старый том `experiment_data` сохраняется для резервных копий и переноса данных из прежней SQLite-версии.

Для ускоренного пилотирования откройте [http://localhost:3010/?demo=1](http://localhost:3010/?demo=1). На видеоэкране появится служебная кнопка завершения клипа, остальные этапы и сохранение данных останутся рабочими.

Отдельный опросник тревоги открывается по адресу [http://localhost:3010/anxiety](http://localhost:3010/anxiety) и привязывается к ID уже созданной сессии.

Панель результатов открывается по адресу [http://localhost:3010/admin](http://localhost:3010/admin). Вход выполняется по `ADMIN_PASSWORD`. Только авторизованный администратор может скачать ZIP одного участника или общую выгрузку всех сессий; участникам ссылки на данные не показываются.

## Проверка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
PYTHONPATH=backend .venv/bin/python -m unittest discover -s backend/tests -v
npm run build --prefix frontend
```

## Видеофайлы

В `clips/` должны находиться 30 нарезанных клипов и два тренировочных ролика `practice_1.mp4`, `practice_2.mp4`. Имена основных файлов должны совпадать с `data/stimuli.json`, например `video_1_c01.mp4` и `video_1_c10_tail.mp4`.

Три полных исходных видео можно автоматически нарезать по таймкодам матрицы:

```bash
python scripts/cut_videos.py /путь/к/исходным-видео clips
```

## Что реализовано

- операторский запуск по ID, полу, возрасту и образованию;
- заранее сформированные 30 слотов: каждый сегмент по 10 раз попадает в каждое условие, все порядки видео и NASA-TLX сбалансированы;
- сохраняемая рандомизация вариантов ответа и итогового теста по ID участника;
- 27 сегментов и 3 финальных клипа;
- фиксация, обязательный комментарий, оценка, окно восстановления и ответ;
- итоговый тест из 27 вопросов;
- три блока модифицированного NASA-TLX;
- проверка манипуляции и дебрифинг;
- отдельный маршрут `/anxiety` для опросника тревоги, не включённый в основной эксперимент;
- событийные метки, AOI и выгрузка пяти файлов CSV/JSON.

## Продакшен

На сервере проект использует локальные порты `3011` и `8011`; наружу его публикует Caddy по HTTPS.

```bash
cp .env.example .env
docker compose up -d --build
curl -fsS http://127.0.0.1:8011/api/health
```

Перед первым производственным запуском замените `POSTGRES_PASSWORD` в `.env` на длинный случайный пароль. Если сервер обновляется с SQLite-версии, сначала сделайте копию `/data/experiment.sqlite3`, запустите только PostgreSQL и перенесите данные до переключения backend:

Также обязательно задайте разные случайные значения `ADMIN_PASSWORD` и `ADMIN_SECRET_KEY`. Первое используется для входа в `/admin`, второе - для подписи временных администраторских сессий.

```bash
docker compose up -d db
docker compose build backend
docker compose run --rm backend python -m app.migrate_sqlite
docker compose up -d
```

Миграция проверяет количество строк во всех трех таблицах и останавливается, если целевая PostgreSQL уже содержит данные. Это защищает существующие записи от случайной перезаписи.

Проверить состояние базы можно так:

```bash
docker compose exec -T db psql -U "${POSTGRES_USER:-ai_hints}" -d "${POSTGRES_DB:-ai_hints}" \
  -c "SELECT (SELECT count(*) FROM sessions) AS sessions, (SELECT count(*) FROM events) AS events, (SELECT count(*) FROM records) AS records;"
```

Пример блока Caddy находится в `deploy/Caddyfile.example`. До выпуска сертификата DNS-запись `A` для `edu1.datascope.online` должна указывать на IP сервера.

Перед реальной сессией оператор должен проверить разрешение 1920x1080, полноэкранный режим, отключение уведомлений и скринсейвера, а также провести приёмочный тест маркеров вместе с лабораторным оборудованием.

## Методические ограничения первой локальной версии

- текст информированного согласия не включён: оператор подтверждает, что согласие оформлено отдельно;
- внешний протокол оборудования в материалах не определён, поэтому метки сохраняются локально; при заданных `MARKER_UDP_HOST` и `MARKER_UDP_PORT` они также отправляются по UDP;
- требование джиттера менее 20 мс необходимо проверять на лабораторном компьютере вместе с оборудованием;
- тренировочный блок использует два нейтральных видеоклипа, не относящихся к учебным материалам;
- прерывание разрешено между роликами; внутри ролика восстановление начинается с текущего сегмента.
- в переданном ТЗ есть ссылки на отсутствующие разделы 10.4, 11, 12.2 и 12.3; текущие тексты проверки манипуляции и дебрифинга требуют содержательного утверждения владельцем исследования;
- системные уведомления и скринсейвер нельзя надёжно отключить из браузера: это часть подготовки лабораторного компьютера;
- отправка маркеров реализована через локальный лог и опциональный UDP; протокол конкретного оборудования необходимо согласовать отдельно.
